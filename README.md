# 推しまとめ(oshi-matome)

推しの X の投稿と、推しへのファンアートタグの投稿を、トピックごとのタブで一覧表示する、個人用の Web サイトです。
学習のアウトプットと、ポートフォリオを兼ねて作りました。

## できること

- 「推しの投稿」と「ファンアート」を、タブで切り替えて表示する
- 投稿をカードで表示する(アイコン、投稿者名、@ID、投稿日時、本文、画像、「Xで見る」リンク)
- 画像を、枚数(0〜4枚)に応じた並べ方で表示する
- 新しい順に20件ずつ表示し、「もっと見る」で続きを読み込む
- サイトを開くと、保存済みの投稿をすぐに表示し、裏で、開いているタブの新しい投稿だけを取得する(差分取得)
- 新しい投稿が取れたら「最新の投稿があります」を一覧に重ねて知らせ、タップで一覧の上に足す
- 更新ボタンで、好きなときに、開いているタブの新しい投稿を取りに行く
- 投稿をお気に入りにでき、お気に入りはタブの上に横スライドで並べる(トピックに関係なく共通)
- 保存期間を過ぎた投稿を、取得のときに消す(お気に入りは残す)
- 読み込み中、0件、取得の失敗、読み込みの失敗を、それぞれ表示する
- スマホの幅でも、崩れずに表示する

## 技術

| 役割 | 技術 |
|---|---|
| フロントエンド | React 19(JavaScript)、Vite 8、素の CSS |
| サーバー | Node.js 24、Express 5 |
| データベース | MySQL 9.7 |
| DB 接続 | mysql2(ORM は使わず、SQL を直接書く) |
| 開発用 | concurrently(画面とサーバーを1つのコマンドで同時に起動) |

## 仕組み

```
ブラウザ(React)
   │  API 1:トピックの一覧
   │  API 2:開いているタブの新しい投稿の取得(差分だけ)と、古い投稿の削除
   │  API 3:投稿の一覧(20件ずつ)
   │  API 4:お気に入りを付ける・外す
   │  API 5:お気に入りの一覧
   ▼
Express ──→ MySQL(topics、posts、media)
   │
   └─ fetcher(取得処理)── サンプルデータ(X API v2 の形式)
                           ※ X API 用は、あとで追加
```

## 設計で考えたこと

- **X API に切り替えやすい作りにする**
  サンプルデータを X API v2 の返却形式に合わせ、取得処理(fetcher)を `.env` の設定で切り替えられるようにしました。切り替えるときに新しく作るのは、X に問い合わせる部分だけです。
- **読み取りの件数を最小にする**
  X API は従量課金のため、前回取得した最新の投稿より新しいものだけを取得し(差分取得)、同じ投稿を二度保存しないようにしています。取りに行くのは開いているタブだけで、さかのぼる時間と1回の件数の上限も `.env` で絞れます。
- **待たせずに表示する**
  サイトを開いたら、取得を待たずに保存済みの投稿を表示し、取得は裏で行います。新しい投稿は、読んでいる位置を急に動かさないよう、お知らせを押したときに足します。
- **データを増やしすぎない**
  保存期間(`.env` で日数を指定)を過ぎた投稿は、取得のときに消します。お気に入りにした投稿だけは残します。
- **SQL を1か所にまとめる**
  SQL は `server/db/` の中だけに書き、API の入口(`server/routes/`)と分けています。開発の途中で DB を MariaDB から MySQL に切り替えましたが、アプリのコードは変えずに済みました。
- **おかしな入力を、入口で断る**
  不正なトピック番号・投稿番号・件数の指定には 400 / 404 を返し、項目の欠けた投稿は保存せずにログへ記録します。`.env` の必須項目が足りないときや、数の項目に正しくない値が入っているときは、サーバーを起動しません。
- **秘密の情報を、コードと分ける**
  DB の接続情報は `.env` に置き、Git の管理から外しています。アプリは、対象の DB の読み書きだけができる専用のユーザーで接続します(表の形を変える権限は持たせていません)。
- **仮のデータで先に画面を作る**
  画面を仮のデータ・仮の API で動かしてから、本物の API に差し替える順番で進めました。API が返すべき形を、先に画面の側から確かめるためです。仮の API は本物と同じ関数名・同じ返す形にしたので、差し替えでは読み込み先を変えるだけで済みました。

## 動かし方

Node.js 24 と MySQL 9.7 が入っていることを前提にしています。

### 1. コードを取得する

```
git clone https://github.com/yugame28-lgtm/oshi-matome.git
cd oshi-matome
```

### 2. データベースを用意する

MySQL に root でログインし、テーブルと初期データを作ります(`source` を使うため、`--commands` を付けます)。

```
mysql -u root -p --default-character-set=utf8mb4 --commands
```

```sql
source server/db/schema.sql
source server/db/seed.sql

-- アプリ専用のユーザーを作り、この DB の読み書きだけを許可する(パスワードは自分で決める)
CREATE USER 'oshi_app'@'localhost' IDENTIFIED BY 'ここにパスワード';
GRANT SELECT, INSERT, UPDATE, DELETE ON oshi_matome.* TO 'oshi_app'@'localhost';
```

### 3. 設定ファイルを作る

`server/.env.example` をコピーして `server/.env` という名前にし、値を入れます。

```
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=oshi_app
DB_PASSWORD=手順2で決めたパスワード
DB_NAME=oshi_matome
FETCH_SOURCE=sample
RETENTION_DAYS=
FETCH_RANGE_HOURS=
FETCH_MAX_COUNT=
```

下の3つ(保存する日数、さかのぼる範囲(時間)、1回に取る件数の上限)は、空なら働きません。サンプルデータは投稿日が古いため、試すとき以外は空のままにしてください(数字を入れると、何も取れない、または投稿がすべて消えます)。

### 4. 起動する

最初の1回だけ、3か所でライブラリを入れます。

```
cd server
npm install
cd ../client
npm install
cd ..
npm install
```

プロジェクトの直下で、サーバーと画面を同時に起動します。止めるときは Ctrl+C を押します。

```
npm run dev
```

ブラウザで `http://localhost:5173/` を開きます。最初に開いたときに、サンプルデータが取り込まれて表示されます。

## ディレクトリ構成

```
oshi-matome/
├── package.json         画面とサーバーを同時に起動するためだけのもの
├── client/              画面(React + Vite)
│   └── src/
│       ├── components/  画面の部品(部品ごとに CSS を置く)
│       └── api/         サーバーとの通信
├── server/              API(Node.js + Express)
│   ├── routes/          API の入口
│   ├── db/              テーブル作成 SQL、DB 接続、SQL を書く処理
│   ├── fetcher/         取得処理(取得元を切り替えられる)
│   └── sample/          X API v2 の形式に合わせたサンプルデータ
└── docs/                設計書と、作業の記録
```
