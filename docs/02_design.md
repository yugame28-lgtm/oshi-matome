## 2. データ

### 2-1. 共通
- DB:MySQL 9.7系(LTS)。公式インストーラーで導入し、Windowsのサービスとして動かす(PCのシャットダウン時に正常終了させるため)。
- 文字コードは utf8mb4(絵文字対応)。初期設定に頼らず、DB作成時とテーブル作成時に明示的に指定する。
- アプリからは専用ユーザー(このDBだけを操作できる権限、パスワードあり)で接続する。root(パスワードあり)は、DBやユーザーを準備するときだけ人が使う。
- 日時はすべて同じタイムゾーンで保存する(UTCを推奨、表示時に日本時間へ変換)。

### 2-2. topics(トピック)
初期データとして2行を登録する。画面からの追加・編集はなし。

| name | 文字列 | ○ | タブ表示名 |
| query_type | 文字列 | ○ | user(アカウント指定)または hashtag(タグ指定) |
| query_value | 文字列 | ○ | @IDまたは#タグ |
| last_fetched_at | 日時 | | 最終取得時刻。未取得なら空 |
| last_post_id | 文字列 | | 前回取得した最新の投稿ID(差分取得の目印)。未取得なら空 |

### 2-3. posts(投稿)
| カラム | 型 | 必須 | 備考 |
|---|---|---|---|

| カラム | 型 | 必須 | 備考 |

### 2-5. 関係
- topics 1 対 posts 多
- posts 1 対 media 0〜4
- 同じ投稿が両方のトピックに当てはまる場合は、トピックごとに1行ずつ保存する(両方のタブに表示)。

### 2-6. 並び順
- posted_at の新しい順。同じ日時なら id の大きい順。

### 3-2. ディレクトリ構成
```
oshi-matome/
├── CLAUDE.md
├── package.json      画面とAPIを同時に起動するためだけのもの(concurrently)
├── docs/
├── client/
│   └── src/
│       ├── components/   部品とその部品用CSS
│       └── api/          サーバーとの通信処理
└── server/
    ├── routes/           APIの入口
    ├── db/               テーブル作成SQL・初期データ・DB接続・SQLを書く処理
    ├── fetcher/          取得処理
    │   ├── sample用      サンプルデータから取得
    │   └── X API用       あとで追加
    ├── sample/           サンプルデータ(pending/ は、まだ届いていない追加分の置き場)
    └── .env              Git管理外
```
- client と server はそれぞれ自分の package.json を持つ。直下の package.json は、両方の起動をまとめるだけで、アプリの部品は持たない。
- SQLは server/db/ の中だけに書く(DB変更時の影響を db/ に閉じ込める)。

### 3-3. 取得処理(fetcher)の方針
- 取得元は .env の設定(sample / x)で切り替える。
- どちらの取得元も、同じ形のデータを返す(トピック、前回の最新投稿IDを受け取り、それより新しい投稿の一覧と、今回の最新投稿IDを返す)。
- 取得したデータは、X API v2と同じく「投稿本体」「ユーザー情報」「画像情報」に分かれている前提で、IDで突き合わせてカード用の形に組み立てる。

### 3-4. サンプルデータの形式(X API v2に合わせる)
| まとまり | 主な項目 | 備考 |
|---|---|---|
| 投稿本体の一覧 | id、text、created_at、author_id、添付画像のキー一覧 | |
| ユーザー情報の一覧 | id、name、username、profile_image_url | 投稿本体の author_id と対応 |
| 画像情報の一覧 | media_key、type、url | 投稿本体の添付画像のキーと対応 |
| メタ情報 | newest_id(最新の投稿ID) | 差分取得の目印 |
- トピックごとに用意し、各20件超(「もっと見る」が確認できる量)とする。
- 画像0枚・1枚・2枚・4枚の投稿、絵文字を含む投稿を混ぜる。
- 差分取得を確認できるよう、「追加分」のサンプルも用意する。
- 画像URLはダミー画像サービス等のURLを使う。

### 3-5. 起動方法
| 起動方法 | 開ける端末 | 用途 |
|---|---|---|
| 通常起動 | PCのみ(localhost) | 開発、自分のPCでの閲覧 |
- 画面(Vite)とAPI(Express)は、別々のサーバーとして動く。開発中は、直下で `npm run dev` を1回実行すると、concurrently で両方を同時に起動する(2026-10-16 から)。どちらも、このPCからだけ開ける。
- 画面(Vite)からAPIへの通信はViteの中継(プロキシ)を通す。
- 当初は、Tailscaleでつながった自分の端末から開ける「スマホ用起動」も作る予定だったが、取りやめた(2026-10-11)。スマホからの利用は、ネット公開で行う(6-7)。

### 3-6. .env の項目
| 項目 | 必須 | 内容 |
|---|---|---|
| DB接続情報(ホスト・ポート・ユーザー・パスワード・DB名) | ○ | |
| 取得元 | ○ | sample または x |
| 保存する日数(RETENTION_DAYS) | | 過ぎた投稿を、取得のときに消す(お気に入りは消さない)。設計では3。空なら消さない |
| さかのぼる範囲(FETCH_RANGE_HOURS) | | これより前の投稿は取らない。設計では24。空なら絞らない |
| 1回に取る件数の上限(FETCH_MAX_COUNT) | | 新しいものを優先する。数字は未決。空なら絞らない |
| X APIキー | 取得元がxのとき | |
- リポジトリには項目名だけを書いた見本ファイルを置く。
- 数の項目は、入れるときは1以上の整数に限る(それ以外ならサーバーを起動しない)。開発中は、サンプルデータの投稿日が古いため、空のまま使う。
- 取得間隔(時間)は、フェーズ5でなくした(6の変更)。

### 3-7. 認証
| 種類 | 方式 |
|---|---|
| サイト→X | X APIキー(X API切り替え時)。サーバーの .env にのみ置き、ブラウザには渡さない |
| 人→サイト | 現在はなし(このPCからしか開けないため)。ネット公開に備えて、ログインを追加する(6-6) |

### 3-8. セキュリティ上の注意

- .env はGitHubに上げない。
- DB(MySQL)のポートは、Windowsファイアウォールで開けない(PCの中のアプリからだけ使う)。

## 4. API

### 4-1. 一覧
| # | URL | メソッド | リクエスト | レスポンス項目 |
|---|---|---|---|---|
| 1 | /api/topics | GET | なし | topics:id、name、last_fetched_at の一覧 |
| 2 | /api/topics/:topicId/refresh | POST | なし | topic_id、status(fetched)、new_count、deleted_count |
| 3 | /api/topics/:topicId/posts | GET | offset(省略時0) | posts:id、author_name、author_username、author_icon_url、text、posted_at、post_url、is_favorite(true/false)、media(url、position の一覧)/has_more |
| 4 | /api/posts/:postId/favorite | PUT | is_favorite(true/false。JSON で送る) | id、is_favorite |
| 5 | /api/favorites | GET | なし | posts:API 3 と同じ項目の一覧 |

### 4-2. 各APIの動き
- 1:タブ表示用。topics を id 順で返す。
- 2:指定したトピックだけを差分取得して保存し、last_fetched_at と last_post_id を更新する(呼ばれるたびに取りに行く)。取得に成功したら、そのトピックの、保存する日数を過ぎた投稿(お気に入り以外)を消す。取得や保存に失敗したら 500 を返し、取得状況の更新も削除も行わない。削除だけに失敗したときは、ログに残して成功として返す。
- 3:1回20件固定。並び順は 2-6 のとおり。media は position 順。has_more は続きがあるかどうか。
- 4:投稿のお気に入りの印を、送られた is_favorite の状態にする(付ける・外す)。同じ状態を2回送っても結果は変わらない。
- 5:お気に入りの投稿を、トピックに関係なく返す。投稿日時の新しい順(2-6 と同じ)。件数の上限なし。

### 4-3. サイトを開いたときの流れ
フェーズ5で 6-4 の流れに変えた。以下は、フェーズ1〜4の流れ(記録として残す)。
1. API 1でタブを表示する
2. API 2で取得する(この間「読み込み中」)
3. API 1をもう一度呼び、取得後の最終取得時刻(last_fetched_at)を受け取り直す(1で受け取る時刻は取得前の値のため。ヘッダーにはこの値を表示する)
4. API 3で選択中タブの投稿を表示する
- 2が失敗しても3と4は実行し、エラーメッセージと保存済みの投稿を表示する。
- タブ切り替え時と「もっと見る」ではAPI 3のみ呼ぶ。

### 4-4. エラー時のレスポンス
- HTTPステータスと、error(メッセージ)を返す。
| ステータス | 場面 |
|---|---|
| 400 | 入力チェック違反 |
| 404 | 存在しないトピック・存在しない投稿 |
| 500 | サーバー内部・DBのエラー |

## 5. 入力チェック
| 対象 | ルール | 違反時 |
|---|---|---|
| topicId | 正の整数で、存在するトピック | 400(形式違反)/404(存在しない) |
| offset | 0以上の整数。省略時0 | 400 |
| postId | 正の整数で、存在する投稿(保存期間を過ぎて消えた投稿は存在しない) | 400(形式違反)/404(存在しない) |
| is_favorite | true か false(文字の "true" や数は不可) | 400 |
| 送られてきたJSON | JSON として読める形 | 400 |
| 取得した投稿 | 投稿ID・投稿者名・@ID・本文・投稿日時・URLがそろっている。画像は4枚まで | その投稿だけ保存せず、サーバーのログに記録 |
| 重複 | 同じトピックに同じ投稿IDがある | 保存しない(エラーにしない) |
| .env | 必須項目がそろっている(3-6) | サーバーを起動せず、不足項目を表示 |

- 24時間以上取りに行かなかったぶんは、取りこぼす(受け入れる)。

### 6-2. 保存と削除
| 項目 | 内容 |
|---|---|
| 保存期間 | 取得した日時(fetched_at)から3日 |
| 消されないもの | お気に入りにした投稿 |
| 保存する件数の上限 | 設けない(3日以内の投稿は、すべて残す) |
| 消すとき | 新しい投稿を取りに行ったときに、そのトピックについて、あわせて行う |
| 取得に失敗したとき | 消さない |
| 切り替え | 保存する日数を .env の項目にする。空なら消さない(開発中・サンプルデータ用) |
- 表示するときの3日の判定は、入れない。久しぶりに開いた回は、消される前の古い投稿が表示され、裏で消されたあとも、その回は画面に残る。
- 消えた投稿にお気に入りなどの操作をしたときは、失敗を知らせる。

### 6-3. 画面
```
+--------------------------------------------------+
|  推しまとめ      最終取得: 10/12 10:00  [ 更新 ]  |
+--------------------------------------------------+
|  [お気に入り] [お気に入り] [お気に入り]  → 横に   |
+--------------------------------------------------+
|  [ 推しの投稿 ]   ファンアート                   |
+--------------------------------------------------+
|        [ 最新の投稿があります ](一覧に重ねる)   |
|  カード一覧                                      |
```
| 要素 | 内容 |
|---|---|
| 更新ボタン | ヘッダーの右、最終取得時刻のとなり。押すと、開いているトピックの差分を取りに行く。新しい投稿があれば、お知らせをはさまずに表示する。なければ「新しい投稿はありません」と短いあいだ表示する。取りに行っている最中は押せなくし、文字を「更新中」にする |
| お気に入り | サイト名の下、タブの上。トピックに関係なく共通。横にスライドして見る。1件は、一覧のカードを縮小したもの。投稿日時の新しい順。0件のときは、場所ごと表示しない。件数の上限なし。縮小したカードは、幅220px・高さ200pxでそろえる。中身は、小さいアイコン・投稿者名・投稿日時、本文(画像ありは3行、なしは4行まで。こえた分は「…」で省く)、1枚目の画像(残りの高さを使い、はみ出た部分は隠す)、★と「Xで見る」。★でお気に入りを外せる |
| お気に入りのボタン | カードの下段(「Xで見る」の並び)。付いているか外れているかが分かる表示。外した投稿は、保存期間を過ぎていれば、次に消す処理が動いたときに消える |
| 新しい投稿のお知らせ | 自動の取得で、今見ているタブに新しい投稿があるとき、「最新の投稿があります」を一覧に重ねて表示する(下にスクロールしても見える位置にとどまる)。タップすると、新しい投稿を一覧の上に足し、増えたうちのいちばん古い投稿の位置から表示する。お知らせは消える |
| 投稿が0件のときの文言 | 「まだ投稿がありません」→「投稿がありません」 |

### 6-4. サイトを開いたときの流れ(4-3 からの変更)
1. タブを表示する
2. 保存済みの投稿を、すぐに表示する(待たない)。1件もなければ「投稿がありません」
3. 裏で、開いているトピックの新しい投稿を取りに行き、保存期間を過ぎた投稿を消す(取得中の表示は出さない)
4. 最終取得時刻を更新する
5. 新しい投稿が取れていたら、表示が0件のときは自動的に表示し、1件以上のときは「最新の投稿があります」を表示する
- 取得に失敗したら、「取得に失敗しました」を表示する(今と同じ)。
