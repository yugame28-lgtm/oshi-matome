# 01 要件定義

## 1. 目的
- HTML/CSS/React/Node.js/JavaScript/SQLの学習のアウトプット
- 就職活動で見せるポートフォリオ作品

## 2. 想定ユーザー
- 作者本人(ゆーと)のみ。個人利用。
- 現在は、作者のPCでサーバーを動かし、そのPCで閲覧する。
- スマホからの利用は、ネット公開(ログイン付き)にしたときに行う(6の「あとで追加」)。

## 3. 作品の見せ方(就職活動)
| 方法 | 内容 |
|---|---|
| コード | GitHubで公開(.envは除く) |
| 画面 | スクリーンショット |
| 実際の動き | Web面談の画面共有で、自分のPCで動かして見せる |

## 4. サイトの概要
- 推しに関する2つのトピックを、トピックごとにカード形式で一覧表示する。
- トピックは事前に固定で登録する(画面から追加・編集しない)。

| トピック | 取得条件 |
|---|---|
| 推しの投稿 | 推しのアカウント(@ID)の投稿 |
| ファンアート | 推しへのファンアートタグ(#タグ)が付いた投稿 |

## 5. データ取得の方針
- 取得元:サンプルデータ(X API v2の返却形式に合わせて作る)。
- X APIは2026年2月以降、新規は従量課金(読み取り1件あたり約0.005ドル)のため、切り替えは「あとで追加」とする。
- 切り替え時に読み取り件数を最小にする仕組みを、最初から入れておく。
  - 差分取得:前回取得した最新の投稿より新しいものだけを取得する。
  - 取得タイミング(現在の実装):サイトを開いたとき、前回の取得から6時間以上たっているトピックだけ取得する。
  - 取得タイミング(変更予定):サイトを開いたときに毎回、開いているトピックの差分だけを取得する。6時間の決まりはやめる(6の「次に作るもの」)。
  - 取得処理は差し替え可能にし、切り替え時は取得部分(fetcher)だけを変更する。
- X APIへの切り替えの前提条件:Xアカウントでの開発者登録、支払い方法の登録、APIキーの発行。

## 6. 機能の仕分け
### 必須(MVP。実装済み)
- 2トピックのタブ切り替え表示
- 自作カード表示(アイコン・投稿者名・@ID・投稿日時・本文・画像・「Xで見る」リンク)
- 画像は1枚なら大きく、2〜4枚はグリッドで表示
- 新しい順(最新が上)に表示、20件ずつ読み込み(「もっと見る」ボタン)
- 取得した投稿はすべてDBに残す
- サイトを開いたときの差分取得(6時間ルール)
- 読み込み中・0件・取得失敗の表示
- スマホ対応(レスポンシブ)

当初は「Tailscale経由でのスマホからの閲覧」もMVPに含めていたが、取りやめた(2026-10-11)。スマホからの利用は、家のPCの電源に関係なく使えるよう、ネット公開で行うことにしたため。

### 次に作るもの(設計は決定済み。詳細は 02_design.md の 6)
- 取得のタイミングと対象の変更:開くたびに、開いているトピックだけ差分を取得する。更新ボタンでも取得できる。6時間ルールはやめる
- 取得する範囲を24時間以内に絞る。1回に取る件数に上限を設ける
- 保存期間:取得した日時から3日。過ぎた投稿は消す(「取得した投稿はすべてDBに残す」からの変更)
- お気に入り:選んだ投稿は、3日を過ぎても残す。トピックに関係なく、まとめて見られる
- 新しい投稿のお知らせ:開いたらまず保存済みの投稿を表示し、新しい投稿があれば「最新の投稿があります」と知らせる
- ログイン:ネット公開に備えて、使えるのを自分だけにする

### あとで追加
- ネット公開(ログイン付き)。条件は、家のPCの電源に関係なく使えること、使えるのは自分だけであること、Xの料金以外は無料の範囲で済ませること
- X APIへの切り替え(ネット公開先で、サンプルデータのまま動くことを確かめてから)
- 無限スクロール
- 詳細表示(Xの公式埋め込み)
- Tailwind CSS・UIライブラリの導入
- TypeScript化

### やらない
- トピックの追加・編集画面
- 画像の保存(XのURLを参照するのみ)
- AIによる要約
- 定時(時刻指定)の自動取得

## 7. 前提・制約
- サーバーが起動しているときだけサイトを閲覧・取得できる。
- 現在は、サーバーを動かしているPCからだけ閲覧できる。ネット公開したあとは、家のPCが起動していなくても閲覧できる。
- ルーターのポート開放はしない。
- 表示されるのは、サンプルデータ(架空の投稿)。本物の投稿が表示されるのは、X APIに切り替えたあと。

## 未決事項

- ネット公開先(アプリを動かす場所と、DBの置き場所)
- 1回に取る件数の上限の数字
- Xの料金の数え方(投稿の件数だけか、問い合わせの回数も含むか)。回数も数えられる場合は、取得の間隔を見直す
