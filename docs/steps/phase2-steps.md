- もとにした設計書:docs/03_phases.md「フェーズ2」
- 順序の変更:設計書の並び(media テーブル → API 1・タブ → ファンアート → 画像グリッド → もっと見る → 状態表示 → 配色)を、フロントエンド先行に変更(2026-10-06 承認済み)。

  - 本物のAPI:自分で作った Express のAPI(API 1・API 3)。MySQL に入っているデータを返す。X のAPIではない(X APIへの切り替えは「あとで追加」)。

## 1. 仮のAPI  [x]
- 目的:サーバーなしで、タブ・画像・もっと見る・状態表示を作れるよう、本物のAPIと同じ形のデータを返す関数を用意する。
- ファイルと置き場所:`client/src/api/dummyApi.js`(新規)
- 仕様:
  - `fetchTopics()`:トピック2件(id、name、last_fetched_at)を id 順で返す(設計書 4-1 の API 1)。
  - `fetchPosts(topicId, offset)`:投稿を新しい順に20件ずつ返す。形は `{ posts, has_more }`(設計書 4-1 の API 3)。
  - 投稿には media(url、position の配列。position 順)を付ける。画像0・1・2・3・4枚を混ぜる。
  - 推しの投稿は22件(「もっと見る」の確認用。コードで作ってよい)。ファンアートは0件(「まだ投稿がありません」の確認用)。
  - 読み込み中の表示を確かめられるよう、返すまで少し待つ。
  - 失敗の表示を確かめられるよう、失敗させる切り替えを用意する。
- 確認:なし(次の確認はセクション6で、画面を組み立てたとき)
