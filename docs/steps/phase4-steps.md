- あとで追加(X API に切り替えるときに決めて作る。このフェーズでは作らない):
  - スマホから使う手段:ネットに公開する。家の PC の電源が入っていなくても使えること、使えるのは自分だけであることが条件。
  - 未決:自分だけに絞る方法(ログインの方式など)、サーバーと DB の置き場所。設計スレッドで決める。
  - 設計の追加(2026-10-11〜12 にユーザーと決めた内容。GitHub への公開のあとに組み込む。設計書の 02 の 6 に反映済み):
    - 取得のタイミング:サイトを開いたときに、毎回、自動で取りに行く(前回からの差分だけ)。あわせて、更新ボタンでも取りに行ける。6時間ルール(前回の取得から6時間たっていなければ取りに行かない)は、やめる。.env の取得間隔(FETCH_INTERVAL_HOURS)は使わなくなる。要件定義の「取得タイミング」と、フェーズ3の完了条件の1つ(6時間以内は取得されない)からの変更。
    - 取得の対象(基本設計。2026-10-12 ユーザー決定):取りに行くのは、開いているトピックだけ。自動の取得も、更新ボタンも同じ。API 2 は、今の「すべてのトピックをまとめて取得する」形から、「指定したトピックだけを取得する」形に変える。消す処理も、そのトピックだけに行う。
    - タブを切り替えたとき(2026-10-12 ユーザー決定):その回に初めて開いたタブなら、自動で取りに行く(開いたときと同じ流れ。まず保存済みを表示 → 裏で取得 → 新しい投稿があればお知らせ)。同じ回のうちに、すでに開いたことのあるタブへ戻ったときは、取りに行かない(新しくしたいときは更新ボタンを使う)。
    - 取りに行く範囲:24時間以内。それより前の投稿は取らない(24時間以上取りに行かなかったぶんは取りこぼす)。
    - 1回に取る件数の上限:設ける(料金を抑えるため)。数字は、X API に切り替える前に、実際のタグの投稿数を見て決める。
    - 保存期間:取得した日時から3日。お気に入りにした投稿は消さない。保存する件数の上限は設けない(3日以内の投稿は、すべて残す。「もっと見る」ですべて見られる)。
    - 消す処理:新しい投稿を取りに行ったとき(開いたとき、更新ボタンを押したとき)に、あわせて行う。取得に失敗したときは消さない。保存する日数は .env の項目にする。空なら消さない(開発中・サンプルデータ用)。サンプルデータのまま数字を入れて試し、問題がなければ空に戻して、公開先では 3 を入れる。
    - 表示のときの3日の判定:入れない(ユーザー決定)。久しぶりに開いた回は、消される前の古い投稿が表示され、裏で消されたあとも、その回は画面に残る。消えた投稿にお気に入りなどの操作をした場合は、失敗を知らせる。
    - サイトを開いたときの流れ:まず保存済みの投稿(DB に取ってある投稿。お気に入りのことではない)を表示する。裏で、新しい投稿の取得と、古い投稿の削除を行う。取得中の表示は出さない。取得に失敗したら「取得に失敗しました」を出す(今と同じ)。
    - 新しい投稿のお知らせ:開いたときの自動の取得で、今見ているタブに新しい投稿があるとき、「最新の投稿があります」を一覧にかぶせる形で表示する(下にスクロールしても見える位置にとどまる)。タップすると新しい投稿を一覧の上に足し(並び順は新しいものが上のまま)、新しく増えた投稿のうち、いちばん古いものの位置から表示する。そこから上へ読み進める。お知らせは消える。保存済みの投稿が0件のときは、タップなしで自動的に表示する。
    - 更新ボタン:ヘッダーの右、最終取得の時刻のとなりに置く。押すと、開いているトピックの差分を取りに行く。新しい投稿があれば、お知らせをはさまずにそのまま表示する(位置は、増えたうちのいちばん古い投稿から)。なければ「新しい投稿はありません」と短いあいだ表示する。取りに行っている最中は押せなくし、文字を「更新中」に変える。
    - 投稿がないときの文言:「投稿がありません」(今の「まだ投稿がありません」から変更)。
    - お気に入り:追加する。トピックに関係なく共通。置き場所は、サイト名の下・タブの上。横にスライドして見る形で、1件は一覧のカードを縮小したもの。並びは投稿日時の新しい順。0件のときは、場所ごと表示しない。件数の上限は設けない。カードの下段(「Xで見る」の並び)に、付ける・外すボタンを置く。外した投稿は、保存期間を過ぎていれば、次に消す処理が動いたときに消える。
    - 残っている確認:縮小したカードの大きさと高さの扱い、1回に取る件数の上限の数字、X の料金の数え方(投稿の件数か、問い合わせの回数も含むか。回数も数えられる場合は、取得の間隔を見直す)。ログインの設計(7点)は、GitHub への公開のあとに決める。
  - 公開先(2026-10-11 ユーザーの意向):X の料金以外は無料で済ませたい。候補は着手時に、その時点の公式の情報で確かめて選ぶ。
