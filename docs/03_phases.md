## フェーズ1:MVP(推しの投稿を縦に通す)
**内容**
- client(React＋Vite)と server(Express)の土台を作る
- MySQLにDBとアプリ専用ユーザーを作り、topics と posts を作成、topics に2行を登録
  - 実際の作業では MariaDB(XAMPP)で完了条件を満たしたあと、MySQL 9.7 に切り替えて同じ完了条件を確認した(2026-10-06)
- 「推しの投稿」のサンプルデータを posts に取り込む(取り込みは手動実行でよい)
- API 3(投稿一覧)を作る
- 画面に「推しの投稿」のカードを新しい順に20件表示する(画像なし、タブなし)

**完了条件**
- PCのブラウザで、サンプルの推しの投稿が新しい順にカード表示される
- 「Xで見る」で元投稿のURLが新しいタブで開く

---
## フェーズ2:一覧の完成
**内容**
- media テーブルを追加し、サンプルデータの画像も取り込む
- API 1(トピック一覧)を作り、タブ切り替えを実装
- ファンアートのサンプルデータを取り込む
- 画像グリッド(0〜4枚)
- 「もっと見る」(offset、has_more)
- 読み込み中・0件・エラーの表示
- 配色・フォント・余白を整える

**完了条件**
- 2つのタブを切り替えられ、画像付きカードがグリッドで表示される
- 「もっと見る」で21件目以降が下に追加され、最後まで行くとボタンが消える

---
## フェーズ3:取得の仕組み
**内容**
- fetcher(sample用)を作り、取得元を .env で切り替えられる形にする
- API 2(/api/refresh):差分取得、6時間ルール、last_fetched_at・last_post_id の更新
- サイトを開いたときの流れ(API 1→2→1→3)とヘッダーの最終取得時刻
- 入力チェック(topicId、offset、取得した投稿、重複、.env)

**完了条件**
- サイトを開くと、追加分のサンプル投稿だけが新しく表示される
- 6時間以内に開き直しても取得されない(skipped)
- 不正な topicId・offset でエラーが返る

**補足**
- 6時間ルールは、このフェーズで作って完了条件を満たした。そのあと、取得のタイミングを見直すことにしたため、「これから」の変更で外す予定(2026-10-12)。
- 配色・フォント・余白(フェーズ2の内容)は、仮の値のまま進めることにした(2026-10-06)。

---
## フェーズ4:スマホ対応
**内容**
- レスポンシブCSS(スマホ1列、PC中央寄せ)

**完了条件**
- スマホ幅で崩れずに表示される

**取りやめたもの(2026-10-11)**
- 起動方法の切り替え(通常起動/スマホ用起動)
- Tailscaleの導入(PC・スマホ)と接続確認
- 理由:スマホからの利用は、家のPCの電源に関係なく使えるよう、ネット公開(ログイン付き)で行うことにしたため。
